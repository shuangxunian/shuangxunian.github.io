OpenClaw 源码解析 架构

这是 OpenClaw 源码解析系列的开篇。在深入具体模块之前，我们先从宏观视角俯瞰整个项目的架构——五层结构、数据流、关键设计决策，帮你建立起一张清晰的全局地图。

项目规模一览

模块 文件数 代码行数 定位
extensions/ 5,006 820K 插件生态（模型/渠道/工具）
src/agents 1,395 327K Agent 执行引擎
src/gateway 570 161K 网关服务器
src/auto-reply 475 111K 自动回复调度
src/plugins 424 103K 插件 SDK + 运行时
src/config 311 101K 配置系统
ui/ 285 82K WebUI 前端
src/cli 374 68K 命令行界面
src/channels 280 35K 渠道抽象层
src/cron 157 30K 定时任务
src/process 33 5K 进程管理 + CommandQueue

总计约 180 万行 TypeScript——OpenClaw 的体量相当庞大。

数据流：一条消息的完整旅程

以用户在 Telegram 发送一条消息为例，追踪一次完整的请求生命周期：

用户在 Telegram 发消息 "帮我总结这篇文章"
 │
 ▼
┌─ extensions/telegram/ ─────────────────────────────────┐
│ Telegram Bot API 收到 update                           │
│ → 解析消息，调用 Gateway 的 channel delivery 接口       │
└────────────────────────────────────┬───────────────────┘
                                     │
                                     ▼
┌─ src/channels/ ──────────────────────────────────────────┐
│ transport 层标准化消息格式                                │
│ → routing: 根据 account-id 定位对应 session              │
└────────────────────────────────────┬─────────────────────┘
                                     │
                                     ▼
┌─ src/auto-reply/ ────────────────────────────────────────┐
│ 判断是否需要 AI 回复，准备 Agent 执行参数                │
│ → enqueueCommandInLane("session:xxx", agentTask)         │
└────────────────────────────────────┬─────────────────────┘
                                     │
                                     ▼
┌─ src/process/command-queue.ts ───────────────────────────┐
│ 检查 lane 空位 (session max=1, global max=4)             │
│ → 有空位直接 pump()，满了排队等待                        │
└────────────────────────────────────┬─────────────────────┘
                                     │
                                     ▼
┌─ src/agents/pi-embedded-runner/run.ts ───────────────────┐
│ 构建系统提示词 → 加载技能/工具/会话历史/记忆             │
│ → 调用 LLM API（流式接收响应）                            │
│ → LLM 要求调用工具时：执行工具 → 结果回传 → 继续推理     │
│ → 最终回复写入 session transcript 文件                   │
└────────────────────────────────────┬─────────────────────┘
                                     │
                                     ▼
┌─ 回复路由 ──────────────────────────────────────────────┐
│ auto-reply 将回复文本送回 channel                        │
│ → 广播 "chat.done" 事件通知 WebUI                        │
└──────────────────────────────────────────────────────────┘

关键设计决策

了解 OpenClaw 为什么长成现在这样，比知道它长什么样更有价值：

决策 选择 原因 代价
进程模型 单进程 简单、状态共享便利 存在阻塞风险
插件策略 全在 extensions/ 核心精简、按需加载 820K 行仍挂同一进程
会话存储 JSONL 文件 零数据库依赖、可 cat 查看 大文件 readFileSync 阻塞
任务调度 CommandQueue lane 同会话串行、跨会话并行 非真并行，仅调度排序
实时通信 WebSocket 广播 推送 agent streaming stringify 成本随连接线性增长
配置管理 YAML + 热重载 改配置不需重启 增加 generation tracking 复杂度

各模块一句话定位

模块 定位
src/gateway HTTP+WS 服务器，所有外部请求的入口
src/agents AI Agent 执行引擎，LLM 调用与工具编排
src/auto-reply 消息到 Agent 的调度器
src/channels 渠道抽象层，统一多平台消息格式
src/config YAML 配置 + 热重载 + sessions 管理
src/plugins 插件 SDK 与运行时
src/process CommandQueue，唯一任务调度队列
src/cron 类 crontab 的周期性 Agent 触发
src/hooks Webhook 钩子与生命周期管理
src/mcp MCP 协议支持
src/memory 长期记忆入口
src/tts 语音合成
src/canvas-host Canvas 实时可视化（A2UI）
src/cli 命令行界面
src/routing account-id → session 映射
extensions/ 所有插件实现
ui/ Vite + React WebUI
apps/ iOS/Android/macOS 原生客户端
packages/ 独立 npm 包（plugin-sdk 等）
